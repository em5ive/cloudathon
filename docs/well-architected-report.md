# Well-Architected review

Scope: one representative retail application's intended regional architecture. This is a design review, not an AWS Well-Architected certification. Local source and tests are distinct from live evidence; [acceptance-status.md](acceptance-status.md) controls claims. Missing AWS credentials block account-specific verification.

| Pillar | Decisions and business benefit | Evidence to collect and remaining risk |
| --- | --- | --- |
| Operational Excellence | Terraform inputs and provider lock, repeatable packaging, three bounded Lambda services, versions/aliases, logs/alarms and reviewed releases reduce manual work for a small platform team. Wave templates make the method repeatable beyond the POC. | Record plan, deployment owner, artifact hash, release and rollback evidence. Alarm definitions do not prove that someone receives or responds to them; configure an approved operational destination. A local state backend is not a team collaboration solution. |
| Security | CloudFront OAC keeps S3 private; default HTTPS endpoints avoid certificate administration. Cognito access JWT and ownership checks protect orders/tickets. SGs restrict DB traffic to Proxy; TLS verification, forced DB SSL, encrypted Aurora and managed secrets protect data paths. The app uses a limited DB role. | Verify anonymous S3 denial, HTTP redirect, cross-user rejection, certificate failure and actual DB SSL. Remove bootstrap administrative access after initialization. Secret rotation, WAF, CloudTrail coverage and enterprise identity are production reviews; source code is not evidence of completed account configuration. |
| Reliability | Private subnets, endpoint coverage and DB instances span two AZs; Aurora has a promotable reader. Proxy bounds connection churn; request timeouts, rollback, idempotent orders and AI fallback contain failure. This reduces individual host/AZ dependence. | Approved failover and restore tests must measure interruption and reconcile orders. Cognito and regional API/DB dependencies remain; this is not full-region DR or a zero-downtime guarantee. Retry a failed write only with its original idempotency key. |
| Performance Efficiency | Edge-cache static content for remote customers, scale Lambda services independently and bound Aurora capacity. Use row locks/short transactions to preserve inventory. Proxy handles bursts while the default writer endpoint provides consistent transactional reads. | Capture p50/p95 latency, Lambda duration/throttles, DB ACUs/connections, Proxy borrow latency/pinning and remote-client timing. API calls still travel to Oregon. Two DB instances do not imply read load balancing through the writer endpoint. |
| Cost Optimization | Managed compute removes per-web-VM OS operations and some licensing exposure. Endpoint-only connectivity matches the few required services. Bounded ACUs/concurrency, retention, cost assumptions and explicit decommissioning tie spending to migration outcomes. | Verify regional rates and Proxy minimum charges, monitor bill/usage, rightsize rehosted VMs and cancel old contracts. Credits are not economic savings. Serverless, replicas and endpoints can be more expensive than provisioned alternatives for steady workloads. |
| Sustainability | Shared managed capacity, demand-based application scaling and retirement of unused VMs/hardware reduce idle provisioning and repetitive maintenance. Static caching reduces origin requests. | Measure utilization, request/data volume and retired assets; do not claim measured carbon savings. Two active DB instances and endpoints consume a minimum footprint. Consolidate or retire low-value workloads before adding replicas or speculative services. |

Operational objectives to agree before production: workload-specific availability target, order error budget, p95 latency, maximum recovery time/data loss, backup restore frequency, data retention, incident ownership, and approved change windows. Suggested **unvalidated targets** are RTO ≤15 minutes for an AZ/DB failover and RPO ≤5 minutes for a recoverable incident; actual Aurora failover/backup mechanisms have different data-loss properties and must be measured. These are business targets, not claims from this POC. Cross-region backup copies or Aurora Global Database could support a separately costed DR design.

The licensing exit and September 2027 handback must appear in operational reporting alongside technical health: accepted workloads, remaining platform dependencies, renewals avoided, source infrastructure retired, overlapping monthly spend, and observed wave throughput. A healthy POC alone does not close the enterprise migration risk.

Framework reference: [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html).
