The first reviewed Terraform deployment creates infrastructure with bootstrap access. A separately authorized bootstrap invocation initializes schema, sample products and the least-privilege DB application account; it writes the application secret directly to Secrets Manager. A second reviewed plan sets `database_bootstrapped = true` and `enable_bootstrap = false`, enabling application credentials and removing administrative bootstrap access and the temporary Secrets Manager interface endpoints. Proxy's AWS-managed secret retrieval does not require those endpoints; normal functions sign IAM tokens locally. Never present the initial infrastructure apply as a functional application before bootstrap and acceptance tests pass.

The dependencies are: identity/region → approved services/engine/quota checks → dependency packages → Terraform validation → account-specific plan and cost review → explicit apply approval → infrastructure creation → explicit DB bootstrap authorization → schema initialization → reviewed bootstrap-removal plan and approval → authenticated live acceptance tests. Any proposed substitute for Option B requires user approval.

Work can proceed in parallel on separate `terraform/`, `backend/` + `database/`, `frontend/`, and `docs/` areas. Coordinate API response shapes and environment variables before integration. One designated owner manages shared deployments and state. Use `git pull --ff-only origin main`, a feature branch, targeted edits, local checks, commit, push and PR review; commands that push or publish are a teammate's future steps, not actions performed during this implementation. The initial repository has no commits, so create the agreed first commit before a normal pull-based workflow exists.

Remote state is a future approved setup: an encrypted, private, versioned S3 state bucket with Terraform S3 native lockfile support (`use_lockfile = true`) and narrowly scoped access. Terraform state and plans remain sensitive even when managed secrets reduce password exposure. Do not share local state between concurrent owners, copy the reference state, create a backend bucket implicitly, or migrate a backend without approval. See [HashiCorp S3 backend locking](https://developer.hashicorp.com/terraform/language/backend/s3#state-locking).
