# AnyCompany retail modernization proposal

**Decision requested:** approve an evidence-led migration program and, after identity, permissions, plan and cost review, the small representative AWS POC. No deployment or infrastructure change is authorized by this document. This summary is intentionally limited to approximately two printed pages; use the detailed reports for implementation and costs.

AnyCompany faces rising virtualization license fees, hundreds of VMs and a Q4 2027 data-center lease expiration. A small platform team cannot manually rebuild every server. The recommended approach combines rapid, dependency-aware rehosting for suitable legacy workloads with selective modernization that reduces guest OS patching, licensing exposure and tightly coupled releases. Target production migration completion by August 31, 2027 and reserve September for contingency and decommissioning, subject to confirmed contract dates.

The competition POC represents one retail application. Customers receive a static storefront through CloudFront and a private S3 origin. Default AWS HTTPS domains provide managed certificates without custom DNS or ACM provisioning. A Cognito-authenticated HTTPS API invokes independent Products, Orders and Support Lambda services in private application subnets. RDS Proxy pools verified TLS connections to two private Aurora PostgreSQL Serverless v2 instances in separate AZs. Short transactions and customer-scoped idempotency protect inventory and orders. Optional Bedrock provides contextual conversation after the DB read closes, with separately rendered authorized facts and fallback. Tickets require explicit escalation and persist with retry-safe response receipts.

This architecture removes the POC's web VMs and their guest OS maintenance, provides global static-content delivery and makes service changes independent. It retains a managed relational database because transactional stock/order consistency matters. Two DB instances and Proxy have an ongoing cost floor; optional AI adds two-AZ endpoint charges, while temporary bootstrap endpoints are removed. Regional API/data latency remains, and a full-region outage needs a separately designed recovery strategy. No zero-downtime or measured availability claim is made.

Terraform standardizes target networking, security, identity and services; it does not migrate arbitrary VM disks. For the fleet, use reconciled inventory and dependency maps to classify applications, organize migration waves, evaluate AWS Transform for discovery/planning/orchestration and MGN for supported rehosting, test every move group, then authorize cutover and eventual source retirement. The local inventory automation demonstrates one repeatable planning step. Live fleet discovery, replication and license termination remain enterprise work.

Current virtualization, OS, DB and application licensing costs are unknown until invoices and entitlements are supplied. Moving to AWS does not eliminate all licenses. Review BYOL eligibility versus license-included options, retain applicable vendor fees, and use License Manager where useful to track obligations. Savings become real only when source infrastructure and reducible contracts are actually retired; retained rollback copies and committed renewals can delay them.

The POC planning allowance is **$250–$400/month at configured minimum DB capacity**, before usage growth, taxes or discounts, using unverified Oregon planning rates. A verified account/region quote must precede apply. The fleet model is deliberately separate: a fictional $900,000 annual source baseline, $600,000 annual future cost and $350,000 transition cost would save $300,000/year and recover transition cash 14 months after full retirement. These numbers demonstrate a method only; actual savings and payback are unknown.

The repository contains implementation, passing local checks, an editable diagram, operations runbooks and a phased migration plan. Fresh workshop reads verify Oregon discovery capabilities and nine-slot Lambda headroom. Eight Service Quotas read denials remain unverified warnings. The real initial Terraform plan is ready: 115 additions, no changes or deletions. Cost review and explicit approval must precede apply. No deployment, live TLS/model/failover or application acceptance is claimed. Success requires a secure retail journey with recorded evidence and a repeatable path to retire the legacy platform before the lease deadline.
